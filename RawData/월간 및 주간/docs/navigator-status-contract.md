# 내비게이션 작성 상태 계약

## 단일 기준 데이터

- 저장 파일: `RawData/월간 및 주간/회의_안건_현황.xlsb`
- 월간 키: `YYYY-M` (예: `2026-8`)
- 주간 키: `YYYY-M-W` (예: `2026-8-4`)
- 상태: `작성` 또는 `미작성`

## 우선순위

1. GitHub XLSB에서 읽은 행과 아직 업로드되지 않은 로컬 대기 변경
2. 저장된 HTML 상태 및 기존 하드코딩 배열
3. 날짜 기준 미래/미지정 표시

GitHub 행이 없는 기간만 기존 HTML 값을 사용합니다. 따라서 원격 장애가 발생해도 기존 문서의 내비게이션 동작은 유지됩니다.

## 쓰기 무결성

- 화면 클릭은 먼저 로컬 트랜잭션과 추가 전용 변경 이력에 저장됩니다.
- GitHub PUT 전에 최신 원격 SHA를 다시 읽고 병합합니다.
- 동일 키 충돌은 임의 덮어쓰기하지 않으며 대기열에 남깁니다.
- 원격 XLSB가 사라진 경우 자동 재생성하지 않습니다.
- 인증 토큰은 세션 메모리에서만 소비하며 소스나 상태 파일에 저장하지 않습니다.

## 반응형 UI

- 데스크탑: 상태 설명과 새로고침/동기화 버튼을 한 행에 우선 배치합니다.
- 모바일 세로: 상태 설명을 한 줄 전체로 배치하고 버튼과 상태 셀의 터치 영역을 최소 44px로 유지합니다.
