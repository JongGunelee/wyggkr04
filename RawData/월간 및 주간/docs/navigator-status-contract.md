# 내비게이션 작성 상태 계약

## 단일 기준 데이터

- 저장 파일: `RawData/월간 및 주간/회의_안건_현황.xlsb`
- 월간 키: `YYYY-M` (예: `2026-8`)
- 주간 키: `YYYY-M-W` (예: `2026-8-4`)
- 상태: `작성` 또는 `미작성`

## 우선순위

1. GitHub XLSB에서 읽은 행과 아직 업로드되지 않은 로컬 대기 변경
2. 마지막으로 검증된 브라우저 캐시
3. GitHub 행이 없는 기간의 날짜 기준 미래/미지정 표시

월간/주간 HTML에는 작성 상태 목록을 중복 저장하지 않습니다. 한 번 이상 정상 동기화한 브라우저에서는 원격 장애 시 마지막 검증 캐시를 사용합니다.

## 기존 HTML 이관

- 주간 하드코딩 작성 147건은 XLSB의 `작성` 행과 전부 일치합니다.
- 월간 하드코딩 미작성 110건은 `LEGACY_NAVIGATOR_ONLY` 예외코드로 XLSB에 이관했습니다.
- 이관된 과거 월간 행은 내비게이션 표시 전용이며 공식 집계와 통합 현황 카드에는 포함하지 않습니다.
- 이관 도구는 `tools/migrate_legacy_navigator_status.mjs`이며 재실행 시 완전 이관 여부만 검증하고 중복 행을 만들지 않습니다.

## 쓰기 무결성

- 화면 클릭은 먼저 로컬 트랜잭션과 추가 전용 변경 이력에 저장됩니다.
- GitHub PUT 전에 최신 원격 SHA를 다시 읽고 병합합니다.
- 동일 키 충돌은 임의 덮어쓰기하지 않으며 대기열에 남깁니다.
- 원격 XLSB가 사라진 경우 자동 재생성하지 않습니다.
- 인증 토큰은 세션 메모리에서만 소비하며 소스나 상태 파일에 저장하지 않습니다.

## 원본 회의록 자동 대조

- 월간 원본: `JongGunelee/wyggkr`, 패턴 `YYYY/YYYY_MM_회의록.html|pdf`
- 주간 원본: `JongGunelee/wyggkr03`, 패턴 `YYYY/YYYY_MM_WW_회의록.html|pdf`
- 실제 파일이 존재하는 모든 키는 `작성`, 관리 대상이지만 파일이 없는 키는 `미작성`이어야 합니다.
- 원본 저장소 파일 목록이 잘리거나 중복 키가 감지되면 XLSB를 변경하지 않고 실패합니다.
- 자동 대조는 기존 변경이력을 수정하지 않으며 실제 상태가 달라진 행만 새 이력으로 추가합니다.
- GitHub Actions가 매시간 대조하고 변경이 있을 때만 XLSB와 부트스트랩을 커밋합니다.

## 반응형 UI

- 데스크탑: 상태 설명과 새로고침/동기화 버튼을 한 행에 우선 배치합니다.
- 모바일 세로: 상태 설명을 한 줄 전체로 배치하고 버튼과 상태 셀의 터치 영역을 최소 44px로 유지합니다.
